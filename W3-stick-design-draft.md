# The Refugium sitting stick

**Design draft for review.** Boot an offline, disposable graphical session from USB. The holder makes or imports a public plan, sees the sitting in a separate terminal and takes the public hand-back away on a transfer drive. The stick itself keeps no wallet state between boots. The [base memo](B6-base-memo.md) proposes Debian 13 and live-build. The owner decides B6. The design below assumes that base. The dated secure-memory rulings are the sole authority for memory behavior. Implementation choices and proposed new wording in this draft are recommendations for review.

## What the holder does

1. Boot the verified stick on a supported x86-64 UEFI machine. The stick checks its runtime conditions before starting the unprivileged graphical session. On success the first application is Refugium Wallet. The existing wallet UI owns plan creation, its node-status warning and the **Export the plan and start the sitting** button. The folder picker starts in a writable sitting folder in RAM. The offline stick has no Core service. W2 explicitly allows plan export while the node is unsynced. See `design/SPEC_w2_mr_gui_sitting.md@5da720457b:L184` and `design/SPEC_w2_mr_gui_sitting.md@5da720457b:L208` in refugium-wallet.
2. For a sitting created here, use that RAM folder. W2 writes its plan there, launches the terminal and reads the returning files there. For an existing public plan, request read-only access to the incoming transfer medium. Copy the public plan to the RAM folder before starting the helper. The hand-back, closing request and closing response can then be created beside the plan. A read-only input stick is never the helper's output directory. W1's existing-file refusal still applies. See `design/SPEC_w2_mr_gui_sitting.md@5da720457b:L222` and `design/SPEC_mr_sitting.md@c026b9b159:L109`.
3. Keep secret plate payloads in W1's private runtime directory. W3 provides the engraving tools and access to the BOOTSEL USB interface. W6 owns accepting a plate and delivering its encrypted job. W3 does not make a new promise that the current engraving program accepts secret ms1 data. Return verified public files to a deliberately selected output volume. Power off after successful export. On abrupt loss of power, RAM work can be lost. A previously completed export remains on the output medium.
4. The image owns boot and media messages. The application authors own wallet screens, seed prompts, the hand-back format, the closing-check retry and the cleanup messages. Packaging takes a specific revision of each. The W3 tests exercise the real I6 launch and both direct and GUI-launched sittings. A shell which takes a memory lock and then executes W1 loses the lock on execution. The helper must take its own lock. [Linux memory locking](https://man7.org/linux/man-pages/man2/mlock.2.html)

## Kernel and hardware

The stick and node share the signed source revision, build environment, release method and removable-media policy. They have two resolved kernel configurations and distinct images. The stick has exactly loopback and Unix-domain sockets for local applications. Disable network devices, loadable modules, radio and DVB support, HID networking, USB gadget networking, swap and hibernation. Keep the USB host controller, mass storage, USB HID and CDC-ACM host driver. The node can enable the receiver-specific devices later. Substituting a stock or node kernel for the stick kernel fails acceptance even in a VM configured with no NIC. See mnemonic-refugium `design/DESIGN_refugium_os.md@c026b9b159:L73` and `design/DESIGN_refugium_os.md@c026b9b159:L110`.

Linux 6.12.118 is the reference LTS for this draft. With NET enabled and NETDEVICES disabled, Linux still builds the loopback device. With SWAP and MODULES compiled out, their procfs entries can be absent. Treat missing status files as success only after checking that procfs is actually mounted and those options really are disabled in the running kernel. Test boot with a presented Ethernet controller, mass storage and display. Check the linked kernel, its running configuration, the initramfs and the final filesystem. A clean list of loadable modules alone cannot detect a built-in NIC driver. [Linux 6.12.118 driver build rules](https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git/tree/drivers/net/Makefile?h=v6.12.118)

**Proposed v1 hardware target.** x86-64 UEFI with a working GOP framebuffer, xHCI, USB keyboard and pointer, software rendering and a directly attached display. A virtual GPU also supports the VM test. Start the compatibility list with physical Intel and AMD systems that complete the sitting and USB tests. Qualify a model, port and firmware combination before claiming support for it. Offer an external USB keyboard and pointer as the baseline. Measure the image and peak operating memory before advertising a minimum. Secure Boot needs a trusted chain for our own kernel. An unsigned test image for a VM establishes no physical Secure Boot compatibility.

## Session and memory boundary

The root filesystem is read-only. Live writes, home, temporary data, the journal, the display runtime and the sitting folder are volatile. Disable persistent overlays, disk-backed home, resume, kdump and persistent crash or terminal logs. The kernel cannot swap, including to zram. A file picker can browse a read-only input mount. It needs a working session bus and portal backend. Avoid a blanket desktop-services ban that would break W2. The terminal does not expose its text through an accessibility bridge. The GUI's accessibility support is a separate property.

Set the session's soft and hard RLIMIT_MEMLOCK to **67,108,864 bytes** before dropping privilege. The GUI, terminal, helper and direct entry path inherit the ceiling. No special capability bypasses it. Strict W1 acquires MCL_CURRENT | MCL_FUTURE before reading, deriving or displaying secrets. The image must bind strict policy independently of argv, environment, the network markers and the limit itself. I recommend compiling strict behavior into the stick's helper package. Removing a policy file, changing an environment variable or invoking that binary directly then cannot select ordinary-host behavior. A single shared binary plus an immutable policy is also viable if loss of that policy demonstrably fails closed for direct launches. The ordinary-host best-effort mode cannot be selected on the stick. Neither an initial lock failure nor an allocator retry may expose a secret in unlocked memory.

Reserve cleanup storage before accepting input. Under pressure, a safely waiting sitting keeps the lock, the existing hand-back and its retry or quit UI. The exact ruled text is **The wallet check did not run.** When the session cannot continue safely, wipe the buffers the process owns while keeping its lock, clear its RAM files and then exit. Wording must track the actual outcome. An uncatchable kill cannot report cleanup. The terminal and compositor also handle screen contents. Whole-process locking of W1 cannot lock those other address spaces or prove erasure. Test a complete signet sitting and closing check, plus initial failure, later pressure, worker-start failure and signal cleanup on the actual packaged helper. See coordinator `coordinator/status/rulings-secure-memory-2026-11-19.md@23a35505c:L7` and `coordinator/status/rulings-secure-memory-2026-11-19.md@23a35505c:L15`. [Linux memory locking](https://man7.org/linux/man-pages/man2/mlock.2.html)

Keep both existing network-identity markers. The image sets `ID=mr-sitting-stick` and its kernel release ends in `-mr-sitting`. W1 also checks the running network property. B36 already settled the values. The question still open is the implementation of strict memory selection. See `design/DESIGN_refugium_os.md@c026b9b159:L5` and `crates/mr-sitting/src/net.rs@c026b9b159:L10`.

## Terminal choice

Use the packaged Alacritty with zero history, clipboard escape sequences disabled, live reload and IPC disabled, and a root-owned configuration. The image controls the executable resolved as x-terminal-emulator. The launcher accepts W2's execution form, preserves each argv element and gives Alacritty the image configuration. It supplies neither arbitrary terminal options nor recording features. Use a private RAM runtime for any terminal diagnostic files. Omit clipboard-history services and recording launch options. Visible selections and compositor buffers remain outside W1's control. Check fullscreen and resized windows as well as alternate-screen exit. The guaranteed property is absence of accessible history and a terminal text bridge. Screen pixels while the user is reading are necessarily visible.

W2 actually searches its absolute PATH entries and invokes x-terminal-emulator with `-e /bin/sh -c`. Its inner helper environment removes GUI variables. A GUI-only strict-mode environment setting would disappear on the normal path. The independent platform test exercised a Debian Alacritty terminal with an active accessibility bus and non-secret markers. An image-level repeat must include the actual launch chain and a positive control for both scrolling and bus observation. See refugium-wallet `crates/mr-gui/src/sitting_spawn.rs@5da720457b:L15` and `crates/mr-gui/src/sitting_spawn.rs@5da720457b:L120`. [Alacritty configuration](https://alacritty.org/config-alacritty.html)

## USB and image separation

Use a small privileged mount helper. The holder requests a mount and chooses its role. Derive eligibility from the actual block device and USB ancestry, exclude every partition of the running boot medium and all internal disks, and recheck identity immediately before touching a device. Never select the first disk automatically. Incoming media use read-only FAT with nosuid,nodev,noexec. Only a designated public transfer medium is eligible for a write operation. Disallow automatic mounts, journal replay on unsupported filesystems, arbitrary source paths and overwrites. Never expose the secret runtime folder as an export source. W6's BOOTSEL tool speaks usbfs directly. An engraver advertising mass storage must not trigger a filesystem mount. Scope BOOTSEL permissions to the accepted hardware. The current engraver tooling identifies RP2350 BOOTSEL as 2e8a:000f. See mnemonic-engrave `scripts/sh2-flash@8829885954:L46`.

Use the same untrusted import policy on the secret-free node. Its eventual encrypted 32–64 GB data partition, receive interfaces, block import and hardware-signer workflow belong to W4, W5 and W7. Keep node and stick dependencies in separate manifests. The role, architecture, source revisions, package hashes and kernel configuration digest are recorded per image.

## Building and updating

A connected build VM acquires signed Debian metadata and pinned artifacts. Build from a locked snapshot of Debian and Debian Security, the project kernel source and separately pinned mr-sitting, mr, mr-gui, me and patched picotool inputs. Include source and dependency locks, feature selections, compiler versions and licenses. Keep the source of the patched utility in its owning project. Build with fixed timestamps and neutral builder identifiers. Generate two complete images in independent clean build VMs and compare the full byte length and SHA-256 per role, including boot records and compressed filesystem. Keep proof of boot and guest assertions separately from reproducibility evidence. Record the package closure to establish the stick excludes node applications. [Debian snapshot archive](https://snapshot.debian.org/) · [Kernel reproducibility](https://docs.kernel.org/kbuild/reproducible-builds.html)

The publisher signs a role-bound release manifest after these gates. On a separate computer authenticate that manifest using an independently trusted project key, verify the image bytes, write a replacement drive and verify the written extent. Keep the previous verified drive until the replacement passes its boot check. The consultant's work uses disposable virtual disks. Production signing, publishing, physical flashing and hardware qualification take place with their owners.

## Decisions for review

| Decision | Recommendation | Other choice or dependency |
|---|---|---|
| B6 | Debian 13 amd64 with live-build for both roles | Ubuntu 24.04 if native receiver packaging dominates the node work. |
| Terminal | Fixed Alacritty configuration with measured zero history | Reopen a different emulator only with equivalent positive-controlled tests. |
| Strict-mode selection | Build the image's helper with strict behavior compiled in | Use an immutable policy if a missing or unreadable policy cannot weaken direct invocation. New holder text and exit codes are W3 proposals for review. |
| Hardware | Whitelist UEFI GOP, USB HID and tested models | Enlarge the matrix as physical machines pass. Decide whether the first public release requires an enrolled Secure Boot key. |
| Removable media | FAT32 input and separate explicit public export, RAM staging, BOOTSEL over usbfs | Add a filesystem only after its mount and write behavior is qualified. |
| Release trust | Signed full-image manifest and replacement medium | Owner supplies the project's trusted release key and distribution channel before public release. |

The W3 spec is the acceptance contract for exact boot, transfer and release-tool text, status codes and tests. Source inspection, component tests, booted-image tests and physical-device results are recorded separately so the coordinator can see what each checkpoint proves.
