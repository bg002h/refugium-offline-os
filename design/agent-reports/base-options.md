# W3 base choice for the stick and the node

**Recommended B6 ruling, 2026-11-19.** Use Debian 13 (trixie) amd64 and Debian live-build for both images. Pin one kernel source revision and build two project-owned configurations. The stick gets its own package manifest and no receiver software. The node can share Debian packaging, build tools and update procedure while including drivers the stick forbids. Debian's live-build manual explicitly supports custom kernel packages. The choice accepts a concrete cost for W5: some receiver packages need native trixie builds. [Debian 13 lifecycle](https://www.debian.org/releases/trixie/) · [Debian Live package and kernel customization](https://live-team.pages.debian.net/live-manual/html/live-manual/customizing-package-installation.en.html)

The two-image split is binding in `design/DESIGN_refugium_os.md@c026b9b159:L35`. The project owns the kernel and removable-media rules at L110, distinguishes the node at L122, and leaves B6 open at L127. W5 owns three receiver paths, including the TBS driver and S400 Ethernet requirement, at L157. This memo selects a common build foundation. Receiver qualification belongs to W5.

## Release, rebuild and size

On the connected builder, retain the signed archive metadata, exact package files and hashes, kernel source/configuration/toolchain, and pinned application inputs. Normalize kernel build timestamps and embedded builder identifiers. Require two clean builds of the same inputs to produce an identical image SHA-256 before signing the release manifest. Compare the final image bytes, including boot structures and the compressed filesystem. Image equality from identical binary inputs demonstrates repeatable assembly. Source-to-binary reproducibility for an individual package requires its own evidence. [Debian package authentication](https://manpages.debian.org/trixie/apt/apt-secure.8.en.html) · [Linux reproducible builds](https://docs.kernel.org/kbuild/reproducible-builds.html)

Deliver fixes as a new full image. Verify the project signature on a manifest containing release version, image role, byte length and hash against an independently acquired release key. Verify the image, write a replacement medium and check the image-length readback. Distinguish the node's encrypted data partition from its replaceable system image. Verify the new system before retiring the previous medium. Neither stick operation nor recovery requires an online package upgrade. Debian's signed-checksum procedure provides a working model for the signature/hash order. [Debian image verification](https://www.debian.org/CD/verify)

Published amd64 images give scale: Debian 13.0.0 standard live and Xfce live are listed at 1.8G and 3.5G. Ubuntu 24.04.4 live server and desktop are 3.2G and 6.2G. These are the distributors' rounded download sizes for different package sets. No Refugium image, live RAM peak or Buildroot target was measured in this comparison. Record final compressed image bytes and peak RAM through the complete sitting before setting minimum media or RAM requirements. The node's 32–64 GB encrypted persistence allocation is separate (`design/DESIGN_refugium_os.md@c026b9b159:L122`).
