# Kernel, terminal and hardware evidence for the sitting stick

## Which kernel can keep only loopback and still support USB?

### Takeaway

Linux 6.12.118 can build loopback, local Unix sockets, USB mass storage, HID and CDC-ACM together, with loadable modules, network device drivers, DVB, swap and hibernation disabled. This is a resolved Kconfig result. The booted image and physical peripherals need separate tests.

### Cited findings

- The kernel.org 6.12.118 source archive has SHA-256 `08308460320e852ac0745b2be3c7ae1cd81bdad713506ed7d817ba1ec9e1a5a5`. Its stable commit is `b869a5313cbfe7102873d3de318ddb68675146d0`. I checked the archive against the published digest, ran the x86-64 default configuration, edited the configuration, ran upstream `olddefconfig` and inspected the resulting values. [Archive checksums](https://cdn.kernel.org/pub/linux/kernel/v6.x/sha256sums.asc) · [Tagged source](https://git.kernel.org/stable/h/v6.12.118)
- Kbuild always visits the network-driver directory. Within it, `NET=y` builds `loopback.o` independently of `NETDEVICES`. The driver registers the interface named `lo`. Local Wayland and systemd IPC can retain Unix-domain sockets. The systemd baseline lists `UNIX` and its prerequisite `NET`. [Driver build](https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git/tree/drivers/Makefile?h=v6.12.118#n92) · [Loopback selection](https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git/tree/drivers/net/Makefile?h=v6.12.118#n22) · [Interface registration](https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git/tree/drivers/net/loopback.c?h=v6.12.118#n212) · [systemd 257 requirements](https://github.com/systemd/systemd/blob/70bae7648f2c18010187c9cf20093155eaa26029/README#L55-L65)
- The resolved config set `NET UNIX SYSFS DEVTMPFS DEVTMPFS_MOUNT TMPFS USB USB_XHCI_HCD USB_XHCI_PCI USB_ACM USB_HID INPUT_EVDEV USB_STORAGE SCSI BLK_DEV_SD VFAT_FS` to `y`. None of `INET IPV6 PACKET NETDEVICES VIRTIO_NET TUN VETH NETCONSOLE USB_NET_DRIVERS USB_USBNET USB_NET_CDCETHER USB_NET_RNDIS_HOST USB_SERIAL USB_GADGET WIRELESS WLAN BT RFKILL NFC CAN IEEE802154 INFINIBAND MEDIA_SUPPORT DVB_CORE MODULES SWAP HIBERNATION` was enabled. No symbol resolved to `m`. These names omit the common `CONFIG_` prefix. An invisible dependent symbol may be absent from the file. [USB network configuration](https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git/tree/drivers/net/usb/Kconfig?h=v6.12.118) · [CDC-ACM](https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git/tree/drivers/usb/class/Kconfig?h=v6.12.118#n7) · [Mass storage and SCSI disk dependencies](https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git/tree/drivers/usb/storage/Kconfig?h=v6.12.118#n9) · [Media configuration](https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git/tree/drivers/media/Kconfig?h=v6.12.118#n12)
- With `SWAP=n`, the object that registers `/proc/swaps` is absent. Hibernation depends on swap. With `MODULES=n`, expect `/proc/modules` to be absent. Refugium accepts that result at `crates/mr-sitting/src/net.rs@c026b9b159:L39`. If the stick additionally disables kernel core dumps, set `EXPERT=y` first. Under the default x86 configuration, requesting `COREDUMP=n` alone resolved to `y`; with `EXPERT=y` it resolved to `n`. [Swap build](https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git/tree/mm/Makefile?h=v6.12.118#n77) · [Swap proc entry](https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git/tree/mm/swapfile.c?h=v6.12.118#n3047) · [Power dependencies](https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git/tree/kernel/power/Kconfig?h=v6.12.118#n38) · [Module proc entry](https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git/tree/kernel/module/procfs.c?h=v6.12.118#n149) · [Core dump option](https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git/tree/fs/Kconfig.binfmt?h=v6.12.118#n171)
- BOOTSEL uses a different USB interface from the serial port. USB core includes `devio.o`, exposing the device operations libusb uses. Upstream picotool can build without libusb, so the installed tool must demonstrate device access. Refugium’s W6 transport is the BOOTSEL ROM over usbfs, documented at `design/DESIGN_refugium_os.md@c026b9b159:L132` and `design/MNEMONIC-INTEGRATION.md@8829885954:L38`. [USB core build](https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git/tree/drivers/usb/core/Makefile?h=v6.12.118#n8) · [picotool build](https://github.com/raspberrypi/picotool/blob/2041936441b48a3cc53ae3da9e805229fe8f4e18/CMakeLists.txt#L334-L345) · [Read-only device information](https://github.com/raspberrypi/picotool/blob/2041936441b48a3cc53ae3da9e805229fe8f4e18/README.md#L3-L18)

### Inferences

- Gate the final resolved config, the built kernel and its guest. Boot with an emulated physical NIC and a virtio NIC presented. Require the PCI devices to exist, both to remain unbound, and the complete interface set to equal `{lo}`. Check again after USB Ethernet hotplug. Representative negatives in the resolved config include CDC-ECM, RNDIS, virtio-net, wireless, Bluetooth and DVB. Inspect the linked built-in driver inventory and the image files for unexpected drivers or packaged modules. An empty module list alone misses built-in drivers.
- Share the kernel source pin and build machinery between images. Produce distinct configurations and binaries. The node’s Novra Ethernet or TBS DVB requirements cannot be satisfied by the stick binary. The image split and node exemption are explicit in `design/DESIGN_refugium_os.md@c026b9b159:L116`.
- Prove three USB operations separately. Open the CDC-ACM test device and exchange a synthetic fixture. Insert a removable data disk and exercise explicit I5 mounting. As the unprivileged session account, read `picotool info` from a known BOOTSEL board with its storage interface unmounted. Require an actual board identifier or device report. A successful tool version, an enumerated USB device or a mounted UF2 volume alone leaves transport untested.

### Gaps

I did not boot a complete W3 image or attach a physical board. The configuration experiment proves the requested options coexist. A release needs boot and hotplug evidence for the image it distributes.

## Which terminal meets the existing GUI contract?

### Takeaway

Use Debian trixie Alacritty 0.15.1-3 on Wayland, with an image-owned configuration. On an isolated Wayland display, the packaged binary retained zero lines of primary-screen history and did not register an application on a functioning AT-SPI bus.

### Cited findings

- The GUI at `crates/mr-gui/src/sitting_spawn.rs@5da720457b:L123` searches for an executable named `x-terminal-emulator` and supplies `-e /bin/sh -c` followed by positional arguments. Its allowlist at line 20 carries `WAYLAND_DISPLAY` and `XDG_RUNTIME_DIR`. The shell at line 17 starts the sitting with a further cleaned environment. The image can provide a root-owned launcher under that name in the image-controlled search path. [Alacritty command-line contract](https://manpages.debian.org/trixie/alacritty/alacritty.1.en.html)
- I used the Debian amd64 package with SHA-256 `0566e9c94869c0adae79bb8968087f157ef6bd4166bb48be85cfbd4f2f1d5623`. I ran its binary in a private software-rendered Wayland session, displaying 22 synthetic numbered lines on an eight-line primary screen. With `[scrolling] history = 0`, Alacritty’s test grid reported `history_size=0`. With the same workload and `history = 10`, it reported 10. Both processes exited successfully. Upstream clamps the grid’s scroll limit and creates the alternate grid with zero history. [Debian package digest](https://packages.debian.org/trixie/amd64/alacritty/download) · [Grid limit](https://github.com/alacritty/alacritty/blob/0c405d53e74ace2980fc5e6c6d5b710c144bc075/alacritty_terminal/src/grid/mod.rs#L154-L182) · [Alternate grid](https://github.com/alacritty/alacritty/blob/0c405d53e74ace2980fc5e6c6d5b710c144bc075/alacritty_terminal/src/term/mod.rs#L412-L418) · [Test output implementation](https://github.com/alacritty/alacritty/blob/0c405d53e74ace2980fc5e6c6d5b710c144bc075/alacritty/src/window_context.rs#L491-L515)
- I explicitly activated a private AT-SPI bus. `org.a11y.atspi.Accessible.GetChildren` on the registry root listed a GTK4 control application and a GTK portal before Alacritty started. The same applications appeared during both terminal runs. Neither terminal registered. The live terminal process mapped none of the GTK, ATK bridge, AT-SPI or AccessKit libraries checked. The packaged source lock file has no AT-SPI or AccessKit crate entry. [AT-SPI interface](https://gnome.pages.gitlab.gnome.org/at-spi2-core/devel-docs/doc-org.a11y.atspi.Accessible.html) · [Alacritty dependency lock](https://github.com/alacritty/alacritty/blob/0c405d53e74ace2980fc5e6c6d5b710c144bc075/Cargo.lock)
- Debian foot 1.21.0 documents and implements round-up of the normal grid to a power of two. Its scroll-up operation uses initialized grid rows. At 24 visible rows and zero configured history, the allocation still permits 32 rows. This makes `lines=0` an unsuitable basis for a zero-history guarantee. [Released source archive](https://deb.debian.org/debian/pool/main/f/foot/foot_1.21.0.orig.tar.gz) (`doc/foot.ini.5.scd` line 769, `render.c` line 4529, `commands.c` line 21)

### Inferences

- The image launcher should validate the GUI invocation, strip the incoming `-e`, set its trusted config explicitly, and use `exec /usr/bin/alacritty --config-file /etc/refugium/alacritty.toml -e "$@"`. Keep the application argv intact. Set `scrolling.history=0`, `general.live_config_reload=false`, `general.ipc_socket=false` and `terminal.osc52="Disabled"` in the read-only config. Install the terminal’s terminfo entry. Keep temporary files in RAM. Ship the reference recorder and verbose event flags only as invocations for synthetic testing; the production launcher must never pass them. [Settings in the selected release](https://manpages.debian.org/trixie/alacritty/alacritty.5.en.html)
- Repeat the zero-history and active AT-SPI control in the actual image’s acceptance environment. Use a program-driven capture only with public fixture text. A running terminal still holds its visible cells and rendering buffers. The sitting’s process lock cannot make claims about those buffers, the compositor or a user-initiated clipboard selection.

### Gaps

The display test used the exact Debian terminal executable with host graphics libraries and a virtual KWin compositor. It did not run the shipping root filesystem, compositor or GUI. Boot that combination and exercise both launch and return to the GUI before claiming image integration.

## Which hardware should the first image support?

### Takeaway

Target a small named matrix of x86-64 UEFI machines using the firmware graphics framebuffer, a USB keyboard and an xHCI controller. Qualify exact machines with Intel and AMD processors before assigning supported status. A model year alone does not establish working display, input or USB.

### Cited findings

- The older hardware consult records keyboard, touchpad, KMS, NVMe, xHCI and firmware as distinct compatibility concerns in `coordinator/agent-reports/recon-distro-satellite-usb.md@0e1137a214:L48`. Linux can expose compatible EFI graphics framebuffers to simpledrm. A separate virtio GPU backend supports QEMU. In the resolved 6.12.118 experiment, `EFI_STUB SYSFB_SIMPLEFB DRM_SIMPLEDRM DRM_VIRTIO_GPU USB_XHCI_PCI USB_HID INPUT_EVDEV` were built in with `DRM_I915=n` and `DRM_AMDGPU=n`. [Firmware handoff](https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git/tree/drivers/firmware/Kconfig?h=v6.12.118#n186) · [simpledrm](https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git/tree/drivers/gpu/drm/tiny/Kconfig?h=v6.12.118#n83) · [Virtual GPU](https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git/tree/drivers/gpu/drm/virtio/Kconfig?h=v6.12.118#n2)
- Debian ships Weston 14.0.2-1. Its native DRM backend uses KMS and evdev, with Pixman as a software compositor renderer. Alacritty additionally needs working client EGL and GL. The packaged terminal ran on Mesa llvmpipe in the virtual-display experiment. The GUI’s Wayland library checks are at `crates/mr-gui/src/libcheck.rs@5da720457b:L33`. [Debian Weston](https://packages.debian.org/trixie/weston) · [Weston DRM backend](https://manpages.debian.org/trixie/weston/weston-drm.7.en.html) · [Alacritty package](https://packages.debian.org/trixie/alacritty)

### Inferences

- For the first physical test, use x86-64 UEFI GOP, simpledrm, Weston DRM with its Pixman renderer and kiosk shell, and the Mesa software EGL/GL stack including the software DRI driver. Use a local seat with input and DRM permissions. Boot an emulated Q35/OVMF machine with virtio GPU separately. The guest’s virtio display exercises a different driver from the physical firmware framebuffer.
- Start with two ordinary machines that span older and newer controller generations, one Intel and one AMD. For each record manufacturer/model, firmware revision, boot policy, visible resolution, keyboard, return from the sitting, USB controller identity, and the three positive USB tests above. Add on-device keyboard, touchpad, discrete GPU, ARM64, legacy BIOS or a binary authenticated boot chain only after the applicable combination is specified and tested.
- Test the whole journey with the actual image. Launch the GUI, start a public fixture sitting, reach its terminal screen, complete the public fixture, and return to the GUI. If the primary use case requires a built-in keyboard on a particular laptop, either qualify its controller or state that an external USB keyboard is required for that model.

### Gaps

No physical models, firmware revisions, BOOTSEL devices or Secure Boot keys were qualified in this experiment. The matrix and software-rendered kiosk are candidate release targets.
